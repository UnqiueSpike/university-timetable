## 接管复验顺序

1. 按根 README 安装指定 Node/npm，建立本地数据库，迁移、测试数据及认证账户。凭据只留在本机忽略文件。
2. 启动应用和 Zero，用 A、B、教师三个独立浏览器会话验证课表隔离、教师补充、CLASS 公告、忙闲分享及撤销。
3. 运行 `npm run check`、`npm run test:db`、`npm run test:sync`、`npm run test:restore`。记录日期、版本、操作者和结果。
4. 按 [大学部署运行手册](../../ops/README.md) 填写环境参数并检查计划；完成镜像构建和扫描、迁移、部署、HTTPS、健康检查、日志及告警通知。
5. 在大学网络重新验证同步、断线恢复、权限撤回、备份恢复和应用回滚；完成并发及持续负载测量。

## 尚需大学提供或确认

- AWS 账户与访问角色、区域、VPC/私有子网、校园或 VPN 网络范围、DNS/证书、镜像仓库、状态桶和 KMS/Secrets Manager 配置。
- 正式身份开通和核实方式、批准的真实数据及来源；开发数据不得迁入正式环境。
- 教师操作及课程授权清单、群体维护责任；当前公告已发布后不可编辑，只能撤回再发布，CLASS 精确对应班级。
- 分享受控接收人清单、最长 30 天期限及最长 62 天范围等开发规则的业务签收。
- 同步时限、测量网络/负载条件、容量目标、RPO/RTO、告警接收人、备份保留和大学费用预算。
- 另一位开发者/运维接管人的实际复验记录。当前没有代替其签收。

## 已知部署限制

本机无 Docker 和大学 AWS 凭据，镜像构建、真实 Terraform apply、RDS 时间点恢复与基础设施重建未执行。Zero 当前设计为一个私网实例和独立加密 EBS，不是跨可用区高可用；实例损坏与重建期间客户端显示断线。恢复旧数据库前须清除会话、撤销分享并重新核对备份时间之后的成员/权限变化，避免恢复已经撤销的授权。发布前须落实可信代理和认证限流策略。试点部署不等于生产批准。
