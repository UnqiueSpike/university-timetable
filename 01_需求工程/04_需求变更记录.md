# 需求变更记录

## 2026-09-19 开发实现约定（待大学业务签收）

- 教师权限分为操作、课程/群体范围和独立审计查看权。补充内容可写；时间、地点、容量覆盖未扩展。CLASS 公告只面向有效班级成员；群体公告必须具备对应群体授权。已发布公告只允许撤回再发新公告。
- 分享通过管理员维护的接收人关系选择，接收人必须登录。忙闲只含起止时间，完整课表增加科目、类型及地点；分享最长 30 天，查询范围最长 62 天，每次分页重新检查授权。拒绝无限期和任意用户搜索。
- Zero 仅订阅当前用户的不透明变更信号，业务字段仍通过 tRPC 逐次授权读取；授权撤销清理可见结果，短期令牌重新核实会话。详细实测见同步报告，大学网络时限尚未约定。
- 用户要求按需要提供权限，作为本次实现及 Git 同步的继续授权；不等同于大学正式身份核实、批准数据源、云端环境参数或业务验收签收。
- 第八步采用 Terraform 定义大学私网 AWS 候选配置。本地恢复已验证；真实部署、大学恢复演练及接管人员复验仍待大学环境提供。

**质量与变化：**好的需求应清楚、必要、可行、无歧义，并能够验证。性能等要求还需明确测量条件和指标。需求工程持续进行 Elicitation（收集）、Analysis（分析）、Specification（明确记录）、Validation（验证）和 Change Management（变更管理），让团队随着新信息调整约定，并同步相关设计、实现和测试。
