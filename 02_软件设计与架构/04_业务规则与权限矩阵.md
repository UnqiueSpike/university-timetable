# 业务规则与权限矩阵

**状态：待客户确认的草案。** 团队负责整理，客户／业务负责人确认业务规则，大学 IT／安全负责人确认认证、授权及隐私限制，开发与测试据此实现和验证。

依据：[客户项目范围](../00_客户需求/01_课程表系统项目目标与范围.md)、[客户待确认事项](../00_客户需求/04_可行性、项目治理与待确认事项.md)及[用户故事](../01_需求工程/02_用户故事、验收标准与可追溯性.md)。以下“原文要求”表示客户说明中已提出，不代表本草案的细化方案已经审批。

## 1. 业务规则

| 编号 | 规则 | 依据 / 状态 | 关联需求 |
| --- | --- | --- | --- |
| BR-01 | 受保护功能需要身份认证，教职员工按角色获得适当的读取和写入权限。 | 原文要求；具体角色与授予方式待确认 | US-01 |
| BR-02 | 学生查看本人课程表；查看同学课表须符合分享授权，不能因知道记录 ID 就取得访问权。 | 本人查询与受控分享为原文要求；访问校验为细化建议 | US-02、US-04 |
| BR-03 | 有合适数据时显示容量或可用名额；容量含义、数据来源及更新周期需确认。 | 原文要求；建议未知值显示“暂无数据”，不当作零 | US-03 |
| BR-04 | 已验证数据与补充信息须清楚区分；验证依据和有权确认状态的人员需明确。 | 原文要求；具体判定流程待确认 | US-03 |
| BR-05 | 分享须取得学生同意，并限制可见信息和接收范围；比较只能使用获准访问的数据。 | 原文要求；接收方式、字段、期限及撤销规则待确认 | US-04 |
| BR-06 | 教职员工只维护授权范围内、经过批准可修改的字段；不修改选课、分班或正式学术记录。 | 原文要求；可写字段及审批要求待确认 | US-05 |
| BR-07 | 公告支持创建、编辑、发布和撤回，可面向特定课程或用户群体。 | 原文要求；群体定义、目标组合和管理权限待确认 | US-06 |
| BR-08 | 建议仅向目标用户展示已发布公告；草稿不对学生展示，撤回后不再作为有效公告展示。 | 细化建议；是否保留历史展示待确认 | US-06 |
| BR-09 | 教职员工修改应留下基本审计信息；建议记录操作者、时间、对象及操作类型。 | 审计为原文要求；字段、查看权限和保留期限待确认 | US-05、US-06 |
| BR-10 | 有效更新应在双方约定的时限内同步，且同步内容仍受访问权限限制。 | 及时更新为原文要求；时限、测量条件及失败处理待确认 | US-07 |

**与数据模型的衔接：**[数据模型](03_数据模型.md)中的“仅维护补充字段”“指定接收人分享”“公告目标取并集”等，均按待确认的设计假设处理；最终以客户确认的规则为准。

## 2. 权限矩阵

以下“学生”和“教职员工”是业务身份，不预设最终角色名称。**有条件允许**表示同时满足操作权限与记录范围，不代表所有教职员工自动拥有该权限。未明确授予的权限建议默认拒绝。

| 操作 | 未登录用户 | 学生 | 教职员工 | 条件 / 边界 |
| --- | --- | --- | --- | --- |
| 查看学生个人课程表 | 不允许 | 本人或获准分享内容 | 不自动允许 | 查看任意学生私人课表需要另行明确授权 |
| 查看课程详情、容量及来源状态 | 不允许 | 有条件允许 | 有条件允许 | 学生可见课程范围及员工负责范围待确认 |
| 分享和比较课程表 | 不允许 | 有条件允许 | 不因员工身份自动允许 | 分享本人信息；比较内容须获授权 |
| 查看教职员工 Dashboard | 不允许 | 不允许 | 有条件允许 | 只显示获授权课程和记录 |
| 修改批准的信息 | 不允许 | 不允许 | 有条件允许 | 同时检查角色、记录范围及字段白名单 |
| 查看已发布公告 | 不允许 | 目标范围内允许 | 有条件允许 | 员工查看或管理范围需单独授予 |
| 创建、编辑公告 | 不允许 | 不允许 | 有条件允许 | 确认是否可编辑他人公告及选择哪些目标群体 |
| 发布、撤回公告 | 不允许 | 不允许 | 有条件允许 | 可与编辑权限分开；是否需要审批待确认 |
| 查看审计记录 | 不允许 | 不默认开放 | 不默认开放 | 由大学明确授权对象及可见范围 |
| 分配角色和权限 | 不允许 | 不允许自行分配 | 不允许自行分配 | 由大学确定授权流程；不据此新增管理员功能 |
| 修改选课、分班或正式学术记录 | 不允许 | 不允许 | 不允许 | 不在本系统范围内 |

同一人兼具学生与教职员工身份时，按具体操作的授权判断，不因为拥有员工角色就放宽本人课表或分享数据的边界。前端隐藏按钮用于交互提示，实际权限必须由后端检查。

## 3. 客户需要确认的决定

| 事项 | 需要确认什么 | 建议确认方 |
| --- | --- | --- |
| 角色与课程范围 | 有哪些角色，谁负责授予、变更和撤销，如何识别负责的课程 | 业务负责人 + 大学 IT |
| 可修改字段 | 具体字段清单、是否限于补充信息、是否需要审核 | 业务负责人 + 数据负责人 |
| 分享与隐私 | 接收人、分享字段、有效期、撤销及是否允许链接访问 | 业务负责人 + 隐私／安全负责人 |
| 公告与群体 | 群体来源、目标并集或交集、编辑他人公告和发布审批规则 | 业务负责人 |
| 数据可信度与容量 | 容量定义、权威来源、验证流程、过期判定 | 数据负责人 |
| 同步与审计 | 更新时限及测量条件、失败提示、审计查看与保留规则 | 业务负责人 + 大学 IT／安全负责人 |

确认后记录决定与日期，更新[需求变更记录](../01_需求工程/04_需求变更记录.md)，并通过[可追溯列表](../01_需求工程/03_可追溯列表.md)同步受影响的设计、实现和测试。
