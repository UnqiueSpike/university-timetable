# 接口契约

**状态：account.me、timetable.mine/getEntry 已实现，其余接口仍为设计草案。** 根据[系统架构](01_系统架构.md)、[数据模型](03_数据模型.md)、[业务规则与权限矩阵](04_业务规则与权限矩阵.md)和[界面原型](05_界面原型.md)约定前后端调用方式。涉及分享、可写字段及公告审批的规则仍需客户确认。

## 1. 通用约定

| 项目 | 约定 |
| --- | --- |
| 通信方式 | 业务接口采用 tRPC；查询为 Query，写入为 Mutation。下文名称为拟定的 procedure 名称，不是 REST 路径。 |
| 身份认证 | 登录、登出及会话由 Better Auth 处理；业务接口从服务端会话获取当前用户，不接受客户端指定操作者身份。 |
| 权限 | 每次调用同时校验操作权限、记录范围和字段范围；员工身份不自动获得所有课程或学生的访问权。 |
| 字段命名 | 接口使用 camelCase，数据库字段使用数据模型中的 snake_case，由服务端转换。ID 均为不透明字符串。 |
| 时间 | 使用带时区的 ISO 8601 字符串；响应时间统一为 UTC，界面按 Australia/Sydney 展示。查询区间为 `[from, to)`，要求 from < to。 |
| 空值 | 未知容量使用 null；已知为零使用 0。成功但无记录返回空列表，查询失败返回错误。 |
| 分页 | 列表输入 cursor（可选）、limit（默认 20，范围 1–100）；返回 items、nextCursor（无下一页时为 null）。课程表按 startAt、id 稳定排序。 |
| 参数校验 | 服务端执行运行时校验并拒绝未声明字段。标题 1–200 字、正文或补充内容 1–5000 字，为建议上限；去除首尾空白后校验。内容按纯文本处理。 |
| 写入结果 | 事务提交成功后才返回成功并触发同步；教职员工修改与审计在同一事务中保存。 |

## 2. 返回数据

以下为业务返回对象；tRPC 的传输封装不在此重复定义。

| 对象 | 主要字段 |
| --- | --- |
| CurrentUser | id、displayName、grants：`{ permission, scopeType, courseId }[]`；全局授权的 courseId 为 null |
| SourceInfo | id、name、kind；kind 建议为 official / test / supplementary |
| TimetableItem | id、classId、course：`{ id, code, name }`、classType、startAt、endAt、location、source、verificationStatus、sourceUpdatedAt、syncedAt、sourceUpdateFailed、capacity、supplements |
| Capacity | total、available、observedAt、source、verificationStatus；无可用快照时整个 capacity 为 null，未知数值单独为 null |
| Supplement | id、entryId、content、updatedAt、revision；作为补充内容单独展示，不覆盖官方字段 |
| Share | id、ownerId、recipientId、from、to、allowedFields、consentedAt、expiresAt、revokedAt |
| Announcement | id、title、body、status、author：`{ id, displayName }`、targets、publishedAt、withdrawnAt、revision |

verificationStatus 建议采用 verified / unverified，来源类型单独表示；测试来源不能成为经过验证的正式数据。没有来源更新时间时 sourceUpdatedAt 为 null。容量来源选择和过期判定按客户确认的规则执行。

**并发控制建议：**Supplement 和 Announcement 增加整数 revision，每次修改递增；写请求携带 expectedRevision，不一致时返回 CONFLICT。本字段已纳入逻辑数据模型；对应阶段创建物理表时须一并落实，当前尚未实现这两类表。

## 3. 查询课程表与容量

| 接口 | 类型 | 输入 | 输出 | 权限 / 需求 |
| --- | --- | --- | --- | --- |
| account.me | Query | 无 | CurrentUser | 已登录；US-01 |
| timetable.mine | Query | from、to、cursor?、limit? | 分页 TimetableItem | 当前学生有效 StudentClass 对应的条目；US-02、US-03 |
| timetable.getEntry | Query | entryId | TimetableItem | 学生所属班级或员工获授权课程范围；US-02、US-03 |
| staff.listEntries | Query | from、to、courseId?、cursor?、limit? | 分页 TimetableItem | 具备读取权限，且限授权课程；US-05 |
| supplement.save | Mutation | entryId、supplementId?、content、expectedRevision? | Supplement | 具备维护权限且条目在授权范围；US-05 |

新建补充记录不传 supplementId 和 expectedRevision；修改必须同时传入，并校验该补充记录属于 entryId。当前暂按仅允许维护 content 设计，待客户确认字段白名单。接口不提供修改官方时间、地点、容量、选课关系或分班的能力。

查询条目按与请求时间区间相交筛选。分页只是传输方式，前端应获取所需区间的全部页，不将单页当作完整课程表。

## 4. 分享与比较

**暂按指定接收人、登录后只读访问设计。** 原型中的公开链接及二维码不构成已批准的分享规则。

| 接口 | 类型 | 输入 | 输出 | 权限 / 需求 |
| --- | --- | --- | --- | --- |
| share.create | Mutation | recipientId、from、to、allowedFields、expiresAt、consent：true | Share | 学生分享本人信息；US-04 |
| share.list | Query | direction：sent / received、cursor?、limit? | 分页 Share | 仅本人创建或接收的授权；US-04 |
| share.revoke | Mutation | shareId | `{ id, revokedAt }` | 仅分享者；重复撤销返回原结果；US-04 |
| share.read | Query | shareId、from、to、cursor?、limit? | 分页获准字段的课程表条目 | 仅指定接收人，授权未过期或撤销；US-04 |
| timetable.compare | Query | shareId、from、to、cursor?、limit? | 分页 `{ side: self / shared, entry }` | 本人课表与该分享获准内容；US-04 |

allowedFields 建议限定为 course、classType、startAt、endAt、location；其中 startAt、endAt 为比较必需字段。实际白名单需确认。返回条目保留不透明 id，其余仅包含获准字段，不包含学生名单、审计或内部权限信息。

服务端记录 consentedAt；接收人必须是大学认可且可分享的账户，不能据此开放任意用户搜索。expiresAt 必须晚于当前时间。读取和比较的区间必须位于授权区间内；比较结果按 startAt、side、id 排序，不计算扩展范围中的冲突检测。

每次读取均重新检查授权，不能仅凭 shareId 放行。分页期间授权失效同样拒绝后续读取。

## 5. 公告

targets 为 `{ type: course, courseId }` 或 `{ type: group, groupId }` 的数组，不能同时填写两种 ID；暂按多个目标取并集设计。

| 接口 | 类型 | 输入 | 输出 | 权限 / 需求 |
| --- | --- | --- | --- | --- |
| announcement.listVisible | Query | cursor?、limit? | 分页公告摘要 | 仅已发布且本人属于目标范围的公告；US-06 |
| announcement.getVisible | Query | announcementId | 公告正文 | 与 listVisible 相同；US-06 |
| announcement.listManaged | Query | status?、cursor?、limit? | 分页 Announcement | 具备管理权限且处于授权范围；US-06 |
| announcement.create | Mutation | title、body、targets | Announcement（draft） | 具备创建权限，所有目标均在授权范围；US-06 |
| announcement.update | Mutation | announcementId、title、body、targets、expectedRevision | Announcement | 具备编辑权限；暂仅允许编辑 draft；US-06 |
| announcement.publish | Mutation | announcementId、expectedRevision | Announcement（published） | 具备发布权限，重新检查所有目标；US-06 |
| announcement.withdraw | Mutation | announcementId、expectedRevision | Announcement（withdrawn） | 具备撤回权限；US-06 |

学生可见的摘要仅返回 id、title、author、publishedAt；正文接口增加 body，不返回完整目标群体名单。公告列表按 publishedAt 降序、id 排序；管理列表按 id 稳定排序。

建议状态流转为 `draft → published → withdrawn`。草稿可暂不填写目标，发布时至少一个目标。已发布公告暂不直接修改正文或目标；如需修改，撤回并新建草稿。是否支持原地编辑、重新发布、编辑他人公告及审批流程，需客户确认后调整本契约。

## 6. 更新同步与数据接入

- **US-07：**业务写入暂统一经 tRPC → 业务层 → Drizzle → PostgreSQL；Zero 承担获授权数据的同步，具体订阅协议另行验证，不在本稿虚构 Zero API。
- 同步通道与查询接口执行相同的行级、字段级授权。撤销分享、公告撤回或成员权限变化后，应移除客户端可见结果；断线重连需重新认证并查询当前状态。
- 数据源故障时保留最近一次成功数据及其时间，明确显示更新失败，不将故障转换为空课表。同步时限和过期阈值待客户确认。
- **FR-01：**外部数据接入属于后端任务，使用批准的数据源配置和服务身份，不开放学生或普通员工直接导入、覆盖官方记录的接口。按来源与外部 ID 去重，完成校验及事务提交后再触发同步。

## 7. 错误与重试

客户端读取 tRPC 错误中的 code，以及扩展信息 reason、requestId；message 为可展示的说明，不返回数据库详情、密钥或调用堆栈。

| code | 使用场景 | 界面处理 |
| --- | --- | --- |
| BAD_REQUEST | 参数格式、时间范围或字段不合法 | 提示修正输入 |
| UNAUTHORIZED | 未登录或会话失效 | 引导重新登录 |
| FORBIDDEN | 不具备该操作权限 | 提示无权操作 |
| NOT_FOUND | 对象不存在或不在可见范围；分享已失效 | 提示内容不存在或不可访问，避免泄露对象是否存在 |
| CONFLICT | revision 不一致，或公告状态不允许该操作 | 刷新数据后重新确认修改 |
| TOO_MANY_REQUESTS | 请求频率超过限制 | 稍后重试，具体限制待确定 |
| INTERNAL_SERVER_ERROR | 服务端或存储异常 | 显示失败与 requestId，保留未提交表单 |

查询可重试；创建分享、补充记录和公告不得在结果未知时自动重发，应先重新查询确认，避免重复记录。写入响应丢失时不能直接提示“保存成功”。

## 8. 确认与关联

实施前需确认：分享白名单和接收方式、可维护字段、公告状态与审批、容量验证规则，以及同步时限。认证供应方及 Better Auth 路由配置另行落实。

本契约覆盖 **US-01～US-07、FR-01**，对应[可追溯列表](../01_需求工程/03_可追溯列表.md)。实现与测试应引用同一接口名称及需求编号；后续规则变化记录到[需求变更记录](../01_需求工程/04_需求变更记录.md)。

## 第四步落实说明

课表使用区间相交 `startAt < to && endAt > from`；一次查询最多 62 天。游标签名并绑定用户与区间，稳定键为 startAt/id；跨页并发变更不承诺快照一致性，刷新重新查询。sourceUpdateFailed 为布尔值，表示该来源/学期最后一次导入失败，此时保留成功记录。客户端必须完整加载所有页，中途错误不作空列表处理。具体实现与容量策略见[课表说明](../app/docs/timetable.md)。
